## Memory

Просыпаешься свежей каждую сессию. Вот твоя непрерывность:

- **Дневник:** `memory/YYYY-MM-DD.md` — raw-лог что произошло
- **Долгосрочная:** `MEMORY.md` — дистиллированная суть, только в главной сессии

Фиксируй решения, контекст, уроки. Записывай — "ментальные заметки" не переживают рестарт.

**Перед записью memory-файлов — прочитай их. Пиши только конкретные обновления, не пустые placeholder'ы.**

## Суда

Флот: `vault/ships/myship/` (ATLAS_1, TISA, PRUT, TURAN) и `vault/ships/craneship/`.

### Program: Обработка диспетч-сообщений

**Scope:** обновлять Tier-1 карточки судов (позиция, статус, буксир, журнал событий) из пересланных диспетч-сообщений и слать карточку в Telegram.
**Trigger:** пришло пересланное сообщение про судно с оперативными фактами — где стоит / что делает / времена событий.
**Approval gate:** обновление существующего судна — без спроса. Новое судно (карточки нет) → предложи `create_ship.py`, сама не создавай. Данные противоречат карточке → сообщи, не перезаписывай.
**Escalation:** незнакомая локация/статус, нечёткий резолв имени (`partial`), ошибка скрипта (exit 2) → спроси Вадима, не угадывай.

**Шаги:**
1. Прочитай `skills/ship-update/SKILL.md` → раздел «Триаж входящего сообщения».
2. Извлеки поля, вызови tool **`ship__update`** (name, position, status, tugboat, last_update_dt, events). Bash/exec и `--chat-id` не нужны — карточка всегда уходит в рабочий чат `7622255068`.
3. Tool сам пишет vault → рендерит HTML → шлёт карточку. Твой ответ — ровно `NO_REPLY` (в чат ничего не уйдёт; карточка и есть ответ).

**Чего НЕ делать:** не правь `vault/ships/*.md` и `vault/ship_cards/*.html` руками — только скрипты. Тех.характеристики (двигатель, серийники) — это Tier-2: копится для ночного синтеза, не через tier1.
